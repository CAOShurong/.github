# Support

Start with the target repository's README, examples, release notes, and open
Issues. If the repository has its own support instructions, use those instead
of this account-wide fallback.

Use a public GitHub issue for a reproducible bug or a focused feature request.
Include the version, environment, minimal input, exact command or sequence,
observed result, and expected result. Remove credentials, private data, device
identifiers, and confidential logs before posting.

These open-source projects do not include a guaranteed response time or
private consulting support. A clear reproduction and a small test case make a
response much more likely.

Security vulnerabilities must not be disclosed in public Issues. Follow
[SECURITY.md](SECURITY.md) instead.
